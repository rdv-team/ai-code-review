# Выражения встроенного языка 1С

### rdv4: Приоритет операторов 1С
- **Ключи:** `Не`, `И`, `Или`, `+`, `-`, `*`, `/`, `%`, `Сравнение`, `Скобки`
- **Критичность:** Важно
- **Инструкция:** При анализе выражений использовать приоритеты встроенного языка 1С, не переносить правила из других языков.

От высокого к низкому:

`.`, `()` → унарные `+ -` → `* / %` → `+ -` → сравнения (`< <= = >= > <>`) → `Не` → `И` → `Или`.

Операторы одного приоритета вычисляются слева направо. Скобки явно задают порядок вычисления.

**Плохо:** считать `Не A = B` как `(Не A) = B`.

**Хорошо:** `Не A = B` разбирается как `Не (A = B)`.

### rdv5: Неподтверждённый контракт динамического результата
- **Ключи:** `Обращение к полю`, `Динамический результат`, `Возвращаемое значение`, `Контракт результата`, `Структура`, `JSON`
- **Критичность:** Важно
- **Инструкция:** Если diff добавляет обязательное обращение к полю динамического результата, а его контракт в diff не представлен, подсветить риск только в `questions_to_author`. Не оформлять его как подтверждённый дефект, не утверждать, что поле отсутствует, и не предлагать `Свойство()` без признаков, что поле опционально. В одном вопросе допускается перечислить все поля.

**Пример:**

```bsl
Результат = ПолучитьДанныеЗадания(ИдентификаторЗадания);
ДокументСсылка = ПолучитьДокументПоИдентификатору(Результат.doc_id);
```

Если обращение к `Результат.doc_id` добавлено в diff, но контракт `Результат` в нём не виден, агент не может подтвердить наличие поля. При его отсутствии выполнение завершится ошибкой на обращении к `doc_id`.

Пример вопроса автору: гарантирует ли `ПолучитьДанныеЗадания()` наличие поля `doc_id` в возвращаемом результате функции?
