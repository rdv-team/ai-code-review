# Программное изменение форм и проведение документов

### rdv2: Многократное программное добавление реквизитов формы
- **Ключи:** `Форма.ИзменитьРеквизиты(МассивРеквизитов)`
- **Критичность:** Критично
- **Инструкция:** Неправильно выполнять вызов `Форма.ИзменитьРеквизиты(МассивРеквизитов)` на каждый новый реквизит. Правильно собрать все новые реквизиты в массив и одним вызовом добавить их на форму: `Форма.ИзменитьРеквизиты(МассивРеквизитов)`.

### rdv3: Проведение документа в транзакции проведения другого документа
- **Ключи:** `Записать(РежимЗаписиДокумента.Проведение)`, `Провести`, `Очередь`, `ФоновоеЗадание`
- **Критичность:** Критично
- **Инструкция:** Неправильно в момент записи основного документа вызывать процедуры проведения зависимых документов в том же пользовательском контексте.
```bsl
// Плохо: много шагов с РО внутри метода отражения заказа клиента
// ... Записать(Проведение) для основного документа ...
// Вызовы: УстановитьСтатусПодготовленДокументаРО, ПереоформитьРасходныеОрдера,
// УстановитьСтатусКОтборуДокументаРО, ПровестиРасходныйОрдер - все в одном методе.
```

Правильно завершить создание и проведение основного документа в текущем методе, поставить работу с зависимыми документами в очередь (фоновое задание, регистр очередей, штатный механизм очередей проекта) и выполнять асинхронно.
```bsl
// После успешной записи основного документа
рдв_РаботаСОчередями.ДобавитьВОчередь(ТипОчередиПереоформитьРасходныеОрдера, ДокументОбъект.Ссылка);
```

### std773: Использование признака ОбменДанными.Загрузка в обработчиках событий объекта
- **Критичность:** Важно
- **Инструкция:** Все обработчики записи объектов (`ПередЗаписью`, `ПриЗаписи`) должны вначале проверять этот флаг для пропуска лишних действий.
