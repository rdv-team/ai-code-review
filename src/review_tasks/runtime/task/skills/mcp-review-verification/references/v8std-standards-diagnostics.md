# Capability: v8std-standards-diagnostics

**Когда использовать:** когда вопрос `verification` зависит от официального стандарта разработки v8std.
**Registry server id:** `onec-v8std-mcp-remote`

## Обозначения

Обозначения: `stdN` — официальные стандарты разработки 1С (N — номер стандарта); `rdvN` — корпоративные стандарты разработки команды.

## Как читать карточку стандарта в `dev-standarts/`

Каждый `### stdN` / `### rdvN` в локальных файлах — маршрут к проверке, не финальное доказательство.

- **Ключи** — фразы и конструкции в changed BSL/SDBL, по которым код связывается со стандартом. Сначала ищи их в видимом фрагменте; совпадение — повод открыть карточку, не повод сразу утверждать нарушение.
- **Инструкция** — что проверить по полному тексту стандарта и когда.
- **Важные уточнения** (если есть) — приоритетные поправки к общему тексту стандарта. При расхождении с v8std MCP или общими знаниями следуй уточнениям; не выводи нарушение, если уточнение явно снимает риск.

## Выбор инструмента

- Используй `v8std_search`, если нужно найти стандарт, диагностику или материал по теме, `stdN`.
- Используй `v8std_get_page`, если нужен полный текст найденного стандарта. Передавай страницу из результата поиска или другого предыдущего MCP-ответа.
- Используй `v8std_get_related`, если нужно перейти от известного стандарта к связанным диагностикам или от диагностики к связанному стандарту.
- Используй `v8std_explain_snippet`, если `stdN` заранее неизвестен и нужно подобрать применимые стандарты по небольшому фрагменту изменённого BSL/SDBL.
- Используй `v8std_explain_diagnostics`, если уже есть конкретные диагностические коды от АПК, BSL Language Server или EDT и нужно объяснить их или сопоставить со стандартами.

Если решение `keep/drop` зависит от содержания конкретного стандарта, получи его полный текст через `v8std_get_page`. Краткого результата `v8std_search`, `v8std_explain_snippet`, `v8std_get_related` или `v8std_explain_diagnostics` для этого недостаточно.

## Ограничения инструментов

### `v8std_explain_snippet`

- `snippet` — **ВАЖНО** не более 500 символов (иначе ошибка сервера `onec-v8std-mcp-remote`).
- Передавай только минимальный нужный фрагмент (1 выражение, вызов, условие или 1–3 строки changed BSL).
- Не отправляй весь метод, модуль или блок с комментариями.
- Если исходный фрагмент длиннее 500 символов, сначала сократи его до минимального участка, достаточного для текущего вопроса `verification`. Если это невозможно, используй `v8std_search`, а затем `v8std_get_page`. Делай несколько `v8std_explain_snippet` только для независимых фрагментов, соответствующих разным вопросам `verification`.

Используй эту `reference` для содержания стандартов разработки v8std, поиска подходящего `stdN`.
