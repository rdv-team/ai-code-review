# Инициализация ревью

Получив задачу и параметры ревью, запусти существующий `review-tasks init`. Уточнение ключа задачи, источника изменений, путей и параметров конкретного запуска относится к этому skill. Установка ПО, настройка Git-доступа, провайдера, локального сервиса и сохранение конфигурации проекта относятся к `review-setup`.

## Вход

- ключ задачи или список ключей задач через запятую — обязательный вход запроса;
- MR ID/URL или просьба найти MR по задачам — необязательно;
- любые явно заданные пользователем параметры, поддерживаемые `review-tasks init --help`: в том числе репозиторий, каталог назначения, ветка/ref, remote, IDE, режим MCP, конфигурация TOML и путь результата;
- `--user-instruction` — только если пользователь явно передал инструкцию;
- `--force` — только если пользователь явно попросил перезаписать завершённое ревью.

### Приоритет параметров

1. Явные параметры текущего запроса имеют приоритет над сохранёнными значениями. Передавай их соответствующими флагами CLI; не заменяй их значениями из конфигурации и не сохраняй переопределения обратно.
2. Для отсутствующих параметров используй запись префикса в `%USERPROFILE%\.review-tasks\prefix-config.json`: `repositories` (устаревшее `repo`), `reviews_dir`, `branch`, `remote`, `ide`, `mcp_enabled`. Пути, ветку и remote движок подставляет сам. IDE и MCP передавай явными флагами: `mcp_enabled: true` → `required`, `false` → `off`; отсутствие поля в существующей записи означает `required`.
3. Если IDE не задана и не сохранена, используй текущую IDE; если её определить нельзя, уточни выбор. Если записи префикса нет и режим MCP не указан, предложи `off` и уточни режим. Не используй память прошлого диалога вместо сохранённых настроек.

Отсутствующая конфигурация префикса сама по себе не является ошибкой: с явными параметрами можно работать без неё. Недостающие данные конкретного запуска запроси у пользователя, объяснив назначение и предложив значение по умолчанию. Если ключ задачи не указан, запроси его здесь, в том числе при наличии MR URL; на этап настройки из-за этого не направляй.

Для TASK основной сценарий — общая ветка проекта, обычно `main` или `master`; для неё можно использовать проверенную ссылку `<remote>/HEAD` (например, `origin/HEAD`). Локальный `HEAD` обозначает текущую позицию рабочей копии. Отдельная ветка задачи не требуется. Выбранный ref должен содержать коммиты нужной задачи. Сохранённый ref — значение по умолчанию, а не ограничение: принимай `-b` для другой ветки. Не ищи автоматически по всем веткам и не подменяй ref. Если коммиты не найдены, сообщи использованный ref и предложи передать другой ref или выбрать MR-режим.

Для задач разных префиксов учитывай отдельные сохранённые значения. Если IDE или режим MCP различаются и пользователь не переопределил их для всего списка, раздели запуск по префиксам. Общие явные переопределения сохраняют приоритет.

### MR URL

CLI принимает в `--mr` только положительный числовой ID. Для URL вида `https://<host>/<group>/<project>/-/merge_requests/42` извлеки `42` из сегмента после `/-/merge_requests/`; параметры запроса и фрагмент URL в ID не включай. Проверь, что хост и полный путь пространства имён/проекта совпадают с выбранным Git remote: учитывай HTTPS, `ssh://` и SSH-форму `git@host:group/project.git`, убирай завершающее `.git`. Не выводи учётные данные из URL remote. Для псевдонима SSH или другого неоднозначного соответствия запроси подтверждение проекта, не угадывай его по номеру MR.

При несовпадении проекта попроси правильный URL либо репозиторий/remote для этого запуска. Не меняй remote. MR URL не заменяет ключ задачи и не требует токена GitLab API: MR refs получает Git. Явный MR допускает одну задачу и один репозиторий; `--mr` и `--mr-from-tasks` несовместимы. В MR-режиме `-b` задаёт базовый ref, а коммиты MR берутся из его ref.

## Запуск

Убедись, что исполняемый файл `review-tasks` доступен. Если его нет, сообщи проблему установки и направь в `review-setup`; `python -m review_tasks` не является допустимым запасным вариантом.

Используй API запуска процессов и настоящий список аргументов. После разрешения параметров пример выглядит так:

```python
argv = ["review-tasks", "init", "-t", tasks, "--ide", ide, "--mcp", mcp_mode]
# explicit_args содержит остальные явно заданные и проверенные по --help
# аргументы, каждый флаг и его значение — отдельные элементы списка.
argv.extend(explicit_args)
if mr_id is not None:
    argv.extend(["--mr", str(mr_id)])
elif mr_from_tasks:
    argv.append("--mr-from-tasks")
if force:
    argv.append("--force")
if user_instruction is not None:
    canonical = user_instruction.replace("\r\n", "\n").replace("\r", "\n")
    argv.extend(["--user-instruction", canonical])
```

Не дублируй уже добавленные флаги в `explicit_args`. Сохраняй пути с пробелами и многострочные значения одним элементом argv. Не собирай командную строку оболочки. Неизвестный или несовместимый параметр уточни по `review-tasks init --help`, не отбрасывай молча. `--user-instruction` допускает 1–2000 Unicode-символов без NUL.

Не переинтерпретируй коды завершения: `0` — успех, `1` — ошибка параметров или конфигурации, `2` — коммиты не найдены, `3` — изменённые пути не найдены. При ошибке покажи безопасный stderr; не повторяй ту же команду без новых данных. Ошибки входных параметров разрешай здесь; при сломанной установке или Git-доступе направь в `review-setup`, не выполняя настройку автоматически.

При успехе выполни `review-tasks check-ready` из каждого созданного каталога задачи. После `True` сообщи каталоги задач и команду открытия выбранного каталога:

- Cursor: `cursor -n "<TASK_DIR>"`;
- Codex: `code -n "<TASK_DIR>"` или `codex -C "<TASK_DIR>"`;
- OpenCode: `opencode "<TASK_DIR>"`.

Следующий шаг в открытом каталоге задачи: `review-start-task`.

При `False` сообщи диагностику и не запускай ревью. Если завершённая задача пропущена, сообщи это без автоматического `--force`.

## Границы

- Не выполняй ревью и не открывай содержимое каталога задачи.
- Не изменяй `review-report-*.md`.
- Не исправляй конфигурацию установки и не сохраняй конфигурацию префикса.
- Не добавляй `--force` без явной просьбы пользователя.
